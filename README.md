# دوخت — سامانه کارگاه خیاطی

سامانه‌ای برای کارگاه‌های خیاطی: هر کسی ثبت‌نام می‌کند، کارگاه خودش را دارد و از ثبت اندازه مشتری
تا انتخاب پارچه، ساخت الگو، تست سه‌بعدی لباس، چیدمان برش و کارت فنی، همه کار را در یک جا انجام می‌دهد.

بر پایه **Laravel 13 / PHP 8.4 / MySQL** با رابط فارسی راست‌به‌چپ.

---

## اصل طراحی: ساده بمان

بنیادی‌ترین قاعده این پروژه این است که کاربر ساده نباید درگیر ده‌ها فیلد و فرم شود:

- **ثبت‌نام** فقط چند فیلد دارد و کارگاه شخصی کاربر همان لحظه ساخته می‌شود؛ اگر رمزش را
  فراموش کند، لینک بازیابی به ایمیلش می‌رود و کارگاهش را از دست نمی‌دهد.
- **اندازه‌گیری** با شش عدد انجام می‌شود (قد، دور سینه، دور کمر، دور باسن، عرض سرشانه، قد آستین) و
  بقیه اندازه‌ها به‌صورت خودکار تخمین زده می‌شوند (`App\Support\Measurements::complete()`).
  دو اصلاح پوسچر (قوز پشت و گودی کمر) هم هست که پیش‌فرضشان صفر است، پس بدن راست
  چیزی نمی‌بیند و فقط وقتی لازم است پر می‌شود.
- **افزودن پارچه** با انتخاب یک پارچه از بانک پایه انجام می‌شود؛ شناسنامه فیزیکی کامل از همان نوع
  پارچه به ارث می‌رسد و در صورت نیاز قابل بازنویسی است.
- هر تنظیم حرفه‌ای پشت یک بخش بازشو (`<x-advanced-section>`) با مقدار پیش‌فرض درست قرار دارد.
- کار روی هر لباس در قالب **پروژه** و در ۱۱ گام پیش می‌رود؛ در هر گام یک پرسش ساده پرسیده می‌شود.
- پس از دوخت، **پرو** روی تن مشتری ثبت می‌شود و همان‌جا به اصلاح الگو تبدیل می‌گردد؛
  پیش از هر اصلاح یک نسخه ثبت می‌شود، پس برگشت‌پذیر است.

## راه‌اندازی

نیازمندی‌ها: PHP ۸.۳ یا بالاتر، Composer، MySQL/MariaDB، Node.js ۲۰ یا بالاتر.

```bash
git clone <repo> dokht && cd dokht
composer install
cp .env.example .env
php artisan key:generate

# ساخت دیتابیس
mysql -u root -e "CREATE DATABASE dokht CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
# سپس در .env مقادیر DB_DATABASE / DB_USERNAME / DB_PASSWORD را تنظیم کنید

php artisan migrate --seed        # جدول‌ها + بانک پارچه، انواع لباس، الگوهای پایه، قواعد و آموزش
php artisan storage:link          # برای نمایش تصویر پارچه و نشان کارگاه

# برای اینکه ایمیل بازیابی رمز واقعاً برسد، در .env تنظیمات MAIL_* را پر کنید؛
# پیش‌فرض MAIL_MAILER=log است و ایمیل فقط در storage/logs نوشته می‌شود.

npm install
npm run build                     # یا npm run dev در حین توسعه

php artisan serve
```

`php artisan migrate --seed` در محیط توسعه یک کارگاه نمونه با مشتری، پارچه، الگو، پروژه و سفارش
هم می‌سازد (`DemoWorkshopSeeder`) تا بدون ورود داده بتوانید همه بخش‌ها را ببینید.

### آزمون‌ها

```bash
php artisan test
```

آزمون‌ها روی SQLite در حافظه اجرا می‌شوند (`phpunit.xml`) و به دیتابیس MySQL دست نمی‌زنند.

## ساختار سامانه

هر «موتور» طرح اولیه در کد یک سرویس مستقل است:

### اندازه کاتالوگ

- **۲۳۶ مدل الگو** در هفده گروه: بالاتنه (۱۳)، تاپ (۱۲)، پیراهن و تی‌شرت (۱۵)، مایو (۱۲)،
  لباس شب و عروس (۱۶)، پیراهن زنانه (۸)، **کت، پالتو و کاپشن (۱۴)**، کت‌وشلوار و لباس رسمی (۴)،
  لباس سنتی و پوشیده (۹)، لباس ورزشی (۵)، لباس زیر (۷)، لباس خواب (۴)، لباس ساحلی (۴)،
  لباس یک‌تکه و کار (۵)، لباس کودک (۵)، آستین (۱۶)، دامن (۳۲)، پایین‌تنه (۲۲) و لباس کامل (۳۳)
- **کت، پالتو و کاپشن**: آزادی از «زیرش چه می‌پوشی» می‌آید (هیچ، پیراهن، بافت، بافت ضخیم)
  و همان عدد روی هر قطعه ثبت می‌شود؛ از پی‌کت و دافل و شنل تا بایکر، پافر، پارکا و بادگیر
- **لباس زیر**: سوتین (بی‌فنر، پوش‌آپ، برالت)، شورت، هیپستر، باکسر و کمبینزون — همه با
  آزادی منفی و کشِ حساب‌شده؛ درز دو تکهٔ کاپ با ساخت برابر است، نه با تنظیم
- **لباس سنتی و پوشیده**: چیپائو، هانبوک، کورتا، شلوارکمیز، ثوب، جلباب، خمار، چادر نماز
  و تونیک پوشیده — هر مدل می‌گوید تا کجای بدن را می‌پوشاند
- **تاپ**: کمیزول، بندو، تانک، راسربک، هالتر، کراپ، آفشولدر، پشت‌باز، بوستیه، یک‌شانه،
  بادی و پینافور — هر کدام بلوک مستقل‌اند، در استودیو نقش بالاتنه را بازی می‌کنند و
  می‌شود روی همه‌شان سبک و برش گذاشت
- **دامن**: از راسته و کلوش و ترک‌دار تا طبقه‌ای (تا هشت طبقه، با چین یا پیلی)، توتوی
  چندلایه، پرنسسی با زیردامن، دنباله‌دار، دولایه، اسکورت، کارگو، پاکتی و کمر کشی
- **پیراهن و تی‌شرت**: دکمه‌دار (کمپ، یقه‌ایستاده، اورسایز، وسترن، یوتیلیتی، اورشرت،
  بلوز جذب)، بی‌دکمه و از سر (پاپ‌اوور، باکسی، آستین‌بلند، رینگر) و دکمهٔ کوتاه
  (پولو، هنلی) — همه روی یک اسکلت مشترک `ShirtBaseGenerator`
- **مایو**: زنانه (یک‌تکه، ورزشی پشت‌کمانی، دامنی، تانکینی، بیکینی مثلثی، بندو،
  برالت، شورت، بورکینی) و مردانه (ترانکس، بردشورت، جامر) — با آزادی منفی بر پایهٔ
  ضریب کشسانی پارچه، کشِ حساب‌شده روی هر لبهٔ باز و نوار فاق
- **لباس شب و عروس**: شب و مجلسی (راسته، خط A، امپایر، پرنسسی، ماهی، اسلیپ اریب،
  ست دوتکه) و عقد و عروسی (عروس پرنسسی با دنباله، عروس خط A، عروس راسته، لباس عقد،
  تور) — بالاتنه از این‌جا و دامن از کاتالوگ دامن، با **رساندن دو کمر به هم** که
  کار اصلی `EveningBaseGenerator` است
- **۷۹ سبک** که روی قطعه‌های آماده اجرا می‌شوند: خط یقه، یقه، آستین یک‌سره با بدنه،
  چین و گشادی، **برش و درز**، لبه، جیب، بست و جزئیات
- **برش**: یوک، پنل طولی، کالربلاک و برش مورب — تنها گروهی که درز تازه می‌سازد و
  روی شلوار و دامن هم مثل بالاتنه کار می‌کند؛ هرچه در این فهرست نبود با «برش دلخواه»
  در ویرایشگر کشیده می‌شود
- **۵۳ نوع لباس**، **۴۴ نوع پارچه** و **۲۹ قاعده طراحی** در بانک پایه
- **یراق** (زیپ، دکمه، قزن، دکمه فشاری، کش و بند) از روی نشانه‌های خود الگو شمرده
  می‌شود و به صورت مواد می‌رود؛ `App\Services\Pattern\NotionCollector`

افزودن مدل یا سبک تازه فقط ساختن یک فایل در `app/Services/Pattern/Generators/` یا
`app/Services/Pattern/Style/` است؛ هر دو رجیستری با پویش پوشه کار می‌کنند و مدل تازه
خودکار در استودیوی طراحی، کتابخانه و پنل مدیریت ظاهر می‌شود.

| موتور | جای آن در کد |
| --- | --- |
| شناخت پارچه (Fabric Intelligence) | `App\Support\FabricProfile`، `App\Services\Fabric\FabricCompatibilityService` |
| موتور قواعد (Rule Engine) | `App\Services\Rules\RuleEngine` + جدول `design_rules` |
| الگوسازی (Pattern CAD) | `App\Services\Pattern\*` (سازنده‌های پارامتریک، جای دوخت، سایزبندی، رندر SVG، خروجی DXF) |
| لباس سه‌بعدی و شبیه‌سازی پارچه | `App\Services\Simulation\ClothPreviewService` + `resources/js/components/garment-viewer.js` |
| تست تناسب (Virtual Fitting) | `App\Services\Fit\FitAnalysisService` |
| برش و چیدمان (Cutting) | `App\Services\Cutting\NestingService`، `LayoutRenderer` |
| تولید (Production) | `App\Services\TechPack\TechPackBuilder`، `App\Services\Export\*` |
| ترکیب و استودیوی طراحی | `App\Services\Pattern\PatternComposer` + `/compose` |
| بازرسی الگو (هر الگویی، نه فقط کاتالوگ) | `App\Services\Pattern\PatternInspector` |
| برش دلخواه (درزی که در هیچ مدلی نیست) | `App\Services\Pattern\PieceSplitter` + دکمه «برش دلخواه» در ویرایشگر |
| سبک‌های برش (یوک، پنل، کالربلاک، مورب) | `App\Services\Pattern\Style\Seam\*` |
| پرو و اصلاح الگو | `App\Support\Alterations`، `App\Services\Fit\AlterationService` + `/projects/{id}/fittings` |
| لباس نامتقارن (سبک روی یک سمت) | `PatternComposer::splitHands()` — هر سبک در استودیو گزینه «دو طرف / راست / چپ» دارد |
| دگرگونی الگو (چرخاندن ساسون، برش و باز کردن) | `App\Services\Pattern\Transform\*` |
| ساخت الگو از عکس و طرح دستی | `App\Services\Vision\*` + `/design-import` |
| بازارچه الگو | `App\Services\Marketplace\*` + `/market` |
| پشتیبان کامل کارگاه | `App\Services\Export\WorkshopBackupService` + دکمه در تنظیمات کارگاه |
| ردّ کار (چه کسی چه کرد) | `App\Models\Concerns\RecordsActivity` + `/workshop/activity` |

### مدل داده

```
Workshop ──┬── User (مدیر، طراح، خیاط، مشاهده‌گر)
           ├── Customer ── MeasurementSet (دفترچه اندازه، تاریخ‌دار)
           ├── Fabric ── FabricType (بانک پایه پارچه با شناسنامه فیزیکی)
           ├── Material (نخ، دکمه، زیپ، لایی، آستر)
           ├── Pattern ── PatternPiece / PatternVersion
           ├── Project ── Simulation / CuttingLayout / TechPack
           └── Order ── OrderItem / Payment
```

داده‌های سراسری (بانک پارچه، انواع لباس، الگوهای پایه، قواعد، آموزش) بین همه کارگاه‌ها مشترک‌اند و
از پنل مدیریت سامانه اداره می‌شوند.

### جداسازی کارگاه‌ها

هر مدل کارگاهی از `App\Models\Concerns\BelongsToWorkshop` استفاده می‌کند:

- `workshop_id` هنگام ساخت به‌طور خودکار از کارگاه فعال پر می‌شود،
- یک اسکوپ سراسری همه پرس‌وجوها را به همان کارگاه محدود می‌کند،
- کارگاه فعال در `App\Support\WorkshopContext` نگه داشته و با میان‌افزار `workshop` تعیین می‌شود،
- برای گزارش‌های سراسری از `->acrossWorkshops()` استفاده می‌شود.

بنابراین هیچ کاربری داده کارگاه دیگر را نمی‌بیند، حتی اگر شناسه را دستی در نشانی وارد کند.

هر کاری که روی مشتری، پارچه، متعلقات، الگو، پروژه، سفارش، پرداخت، پرو و دفترچه اندازه
انجام شود در جدول `activities` ثبت می‌شود — چه کسی، چه زمانی، و کدام فیلد از چه به چه
عوض شد. گزارشش در `/workshop/activity` است و مثل هر داده دیگری به کارگاه خودش محدود.

### واحدها و قراردادها

- همه اندازه‌ها **سانتی‌متر** است؛ مبدأ هر قطعه الگو گوشه بالای خودش، `x` به راست و `y` به پایین.
- `PatternPiece::outline` یک چندضلعی بسته از نقاط `{x, y}` است؛ نقطه‌ای با `curve: true` و نقطه کنترل
  `{cx, cy}` یعنی منحنی درجه‌دو تا آن نقطه.
- شناسنامه پارچه فقط از کلیدهای `FabricProfile::SCHEMA` استفاده می‌کند و
  `FabricProfile::physics()` آن را به پارامترهای موتور شبیه‌سازی تبدیل می‌کند.
- تاریخ‌ها در دیتابیس میلادی ذخیره و در نمایش با `App\Support\Jalali` شمسی می‌شوند؛
  ورودی کاربر با `Jalali::parseJalali()` خوانده و اعداد فارسی با `Jalali::latinDigits()` نرمال می‌شود.

## خروجی‌ها

الگوی قابل چاپ با مقیاس ۱:۱، **PDF برداری چندصفحه‌ای با متن فارسی**، PNG، SVG،
DXF ساده و DXF صنعتی **AAMA/ASTM**، JSON، نقشه برش، برگه اندازه، صورت مواد،
دستور دوخت و کارت فنی (Tech Pack) نسخه‌دار — همه در یک فایل زیپ.

مدیر کارگاه می‌تواند از تنظیمات، **پشتیبان کامل کارگاه** را بگیرد: هر جدول به صورت JSON خام،
مشتری‌ها و سفارش‌ها به CSV خواندنی با اکسل، و فایل‌های بارگذاری‌شده (نشان کارگاه و عکس پارچه‌ها)
— همه در یک زیپ که به سرور وابسته نیست.
